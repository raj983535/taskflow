# TaskFlow feature and business-logic guides

This folder explains what users can do in TaskFlow and how each feature works through the application.

## What belongs here

A feature guide is needed when a meaningful user journey or business rule is added or changed. Examples include creating a task, editing or completing a task, filtering a task list, managing task ownership, or changing access rules, when those features are actually agreed and implemented.

## Required explanation

For each feature, explain:

- The user problem and expected outcome.
- The user journey from the interface to the final result.
- The business rules, validation, conditions, permissions, and state changes.
- The frontend components and state involved.
- The API endpoint and request/response behaviour, when applicable.
- The database tables or records affected, when applicable.
- What happens on success, invalid input, missing data, and server/database failure.
- Tests and manual checks actually performed.
- How to investigate a failure.
- Links to relevant architecture guides and theory lessons.

Do not invent product behaviour to make a feature look complete. Record open questions or explicitly agreed assumptions.
